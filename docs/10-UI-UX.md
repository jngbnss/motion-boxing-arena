# 10. UI/UX 설계

> 기준 문서: [designs/motion-boxing-arena.md](designs/motion-boxing-arena.md). 화면 흐름은 [01-USER-FLOW.md](01-USER-FLOW.md).
> 구현 전 설계 문서다.

## 1. 원칙

- **게임다운 첫인상, 실패에 친절한 화면.** 웹캠·생성·네트워크는 실패가 일상이므로 모든 화면에 오류 상태를 설계한다.
- **몸이 입력이다.** 메뉴는 마우스/키보드로 조작하되, 게임 중에는 손을 키보드에 두지 않아도 되도록 일시정지 제스처를 제공한다.
- **인식 상태가 항상 보인다.** 게임 중에도 작은 인식 표시등(초록/노랑/빨강)을 둔다.
- UI 셸은 React, 게임 캔버스는 Three.js(명령형). HUD는 React 오버레이(DOM)로 그려 캔버스 렌더링과 분리한다.

### 3번 그리기 템플릿
- 512×768 캔버스, 배경에 반투명 **A-pose 실루엣**(팔 45°, 다리 약간 벌림, 정면).
- 도구: 펜(3 굵기), 채우기, 지우개, 색상 12개, 실행 취소. 실루엣 밖 영역은 생성 전 자동으로 투명 처리.
- 목적: 휴머노이드 비율·정면·팔 분리 자세를 유도해 리깅 성공률(T2)을 높인다. 효과는 PoC로 측정(템플릿 vs 자유 업로드 성공률 비교).

## 3. 게임 플레이 HUD 와이어프레임

```
+------------------------------------------------------------------+
| [내 HP ██████████░░ 82]        01:12        [상대 HP ███████░ 64] |
|  내 이름 (T2)                                   상대 이름 (T1)     |
|                                                                  |
|                        (상대 3D 캐릭터)                           |
|                                                                  |
|                      ! 예비동작 표시 (AI)                         |
|                                                                  |
|                                                                  |
|        (왼쪽 글러브+전완)                (오른쪽 글러브+전완)        |
|                                                     +----------+ |
| [● 인식 양호]  JAB  STRAIGHT  GUARD  SLIP            | 미니 웹캠 | |
|  (최근 인식 이벤트 칩, 0.5초 후 사라짐)               | 스켈레톤  | |
|                                                     +----------+ |
+------------------------------------------------------------------+
```

- 미니 웹캠 패널은 설정에서 끌 수 있다. 영상 자체 대신 **스켈레톤만 표시하는 옵션**을 기본값으로 둔다(개인정보·시연 화면 정돈).
- 타격 효과: 상대 피격 시 히트 스파크 + 짧은 카메라 임펄스(0.05m 이하), 내가 피격 시 화면 가장자리 붉은 비네트 + 0.1초 흔들림. 회피 성공 시 "SLIP!" 텍스트와 슬로모션 0.15초(싱글 전용).
- 1인칭에서는 **자기 글러브와 전완만** 표시한다. 몸통·머리는 그리지 않는다(카메라 클리핑·리타겟 오차 회피).

## 4. 랜드마크 디버그 오버레이

캘리브레이션 화면에서는 기본 표시, 게임 중에는 설정·디버깅 화면에서 켠다.

| 요소 | 설계 |
|---|---|
| 스켈레톤 | 사용 랜드마크(코, 귀, 어깨, 팔꿈치, 손목, 손 끝점, 엉덩이)를 선으로 연결. 미러 표시 |
| 신뢰도 색 | visibility ≥ 0.7 초록, 0.5~0.7 노랑, < 0.5 빨강(해당 관절은 판정에서 제외됨을 표시) |
| 정규화 축 | 어깨 중점 원점, 어깨 너비 스케일 박스, 캘리브레이션 중립 머리 위치(점선 원)와 현재 머리 오프셋 벡터 |
| 손별 FSM | 각 손 옆에 현재 상태(IDLE/EXTENDING/PEAK/RETRACTING/COOLDOWN) + 속도 바 + 손 크기 비율 바 + 임계선 |
| 방어 상태 | guard 가중치 게이지, slip 방향 화살표 |
| 이벤트 로그 | 최근 20개 이벤트(`t`, type, hand, confidence), 오인식 의심 이벤트는 회색 |
| 성능 | 렌더 FPS, 추론 FPS, 추론 ms(p50/p95), 프레임 캡처→이벤트 지연, 드롭 프레임 수 |
| 녹화 | ● REC 버튼: 랜드마크 JSONL 녹화(영상 아님). 녹화 중 숫자키로 라벨 입력(1 잽, 2 스트레이트, 3 가드, 4 좌회피, 5 우회피, 0 없음) 또는 "가이드 녹화"(화면 지시에 따라 동작 → 자동 라벨). 저장은 로컬 파일 다운로드 |

## 5. 예외 상황 UI

| 상황 | 감지 | UI | 사용자 행동 |
|---|---|---|---|
| 웹캠 권한 거부 | `NotAllowedError` | 브라우저별 권한 재허용 방법(주소창 카메라 아이콘) 그림 안내 | 재시도 버튼 / 키보드 모드로 플레이 |
| 장치 없음 | `NotFoundError` | "카메라를 찾을 수 없어요" + 연결 확인 | 재검색 / 키보드 모드 |
| 장치 사용 중 | `NotReadableError` | "다른 앱(화상회의 등)이 카메라를 쓰고 있어요" | 앱 종료 후 재시도 |
| 조명 부족 | 프레임 평균 밝기 < 임계 또는 전 랜드마크 visibility 낮음 | "얼굴과 손이 잘 보이게 앞쪽 조명을 켜 주세요" | 계속 진행 가능(경고) |
| 사람 미검출 | 포즈 결과 0명 1초 이상 | 실루엣 가이드 강조 "화면 안으로 들어와 주세요" | — |
| 2인 검출 | `numPoses=2` 설정 시 2명 감지 | "한 명만 화면에 있어야 해요". 게임 중이면 일시정지 | — |
| 손목 화면 이탈 | 손목 좌표가 프레임 밖 or visibility < 0.5 반복 | "카메라에서 조금 더 멀어져 주세요(권장 1.5~2.5m)" | — |
| 생성 실패 | job `FAILED` | 실패 단계와 쉬운 원인("배경이 복잡해요", "사람 모양을 찾지 못했어요") + 다시 시도 + **T0 스킨 모드로 2초 만에 만들기** | 선택 |
| 생성 지연 | 예상 시간 2배 초과 | "평소보다 오래 걸려요. 먼저 한 판 하고 오세요" | 로비로 |
| 생성 완료(경기 중) | job `READY` | 토스트 "3D 캐릭터 준비 완료 – 다음 경기부터 적용". 경기 중에는 교체하지 않고 다음 READY 진입 시 자동 교체(설정에서 끄기 가능) | — |
| 추적 손실(게임 중) | 어깨 visibility < 0.5 또는 미검출이 지속 | 즉시 "인식 끊김" 표시등(이 동안 회피·가드 무효). 싱글 2초 / 온라인 3초 후 일시정지 오버레이 "카메라 앞으로 돌아오세요", 복귀하면 3초 카운트다운. 온라인은 남은 일시정지 예산(누적 30초) 표시 | 화면 안으로 복귀 |
| 상대 커스텀 캐릭터 | — | 상대 캐릭터 메뉴 "기본 외형으로 보기", "신고" | 선택 |
| 서버 연결 실패 | REST/WS 오류 | 상단 배너 "오프라인: AI 대전만 가능" | 재연결 버튼 |
| 경기 중 연결 끊김 | WS close | 전체 오버레이 "재연결 중… 18초" 카운트다운. 상대 화면에는 "상대 재접속 대기" | 자동 재연결 |
| 브라우저 미지원 | WebGL2/`getUserMedia`/WASM 미지원, 비보안 컨텍스트 | 지원 브라우저(최신 Chrome/Edge) 안내 | — |

키보드 모드(J 잽, K 스트레이트, Space 가드, A/D 회피)는 웹캠 실패 시 대체 경로이자 개발용 입력이다. **AI 대전 전용**이며, 온라인 대전은 웹캠이 필수다(결정 기록 C12).

## 6. 안전 안내

- 캘리브레이션 첫 화면: "주변 1.5m × 1.5m를 비워 주세요. 모니터·벽과 팔 길이 이상 떨어지세요." 위 그림 + 확인 체크.
- 카메라 권장 거리 1.5~2.5m. 너무 가까우면(어깨 너비가 프레임 폭의 45% 초과) 경고.
- 일시정지: ESC 또는 **양손을 머리 위로 2초**(싱글). 추적 손실 시 자동 일시정지(싱글 2초, 온라인 3초).
- 장시간 플레이 경고: 연속 10분마다 휴식 권유.
- 펀치는 "허공에, 끝까지 뻗지 않아도 인식됨"을 안내해 관절 과신전을 줄인다.

## 7. 확장 대비: 렌더 출력 인터페이스

홀로그램형 디스플레이는 MVP 범위가 아니지만, 렌더러에 출력 추상화만 예약한다.

```ts
interface ViewOutput {
  id: 'single' | 'pepper-ghost-4view' | 'quilt';
  render(scene: THREE.Scene, cameras: THREE.Camera[], renderer: THREE.WebGLRenderer): void;
}
```

MVP는 `single`만 구현 대상으로 둔다. HUD는 DOM이므로 홀로그램 출력 시 별도 3D HUD가 필요하다(확장 과제).
