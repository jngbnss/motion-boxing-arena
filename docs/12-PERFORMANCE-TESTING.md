## 2. AI 역량 평가 항목 (A~H)

### A. 모델 비교 및 선정
| 영역 | 후보 | 비교 기준 | 결정 시점 |
|---|---|---|---|
| 포즈 | Pose lite(5.78MB) / full(9.40MB) / heavy(30.66MB) | 동작 F1, 추론 ms, 로딩 시간, 내장 GPU FPS | W2 |
| 이미지→3D | TRELLIS.2, TRELLIS v1, SPAR3D, TripoSR, (유료) Meshy | 성공률, 시간, VRAM, 리깅 적합성(팔 분리 여부), 라이선스 | W2 Go/No-Go |
| 배경 제거 | rembg(u2net), BiRefNet | 그림·사진에서의 마스크 품질(육안 5단계) | W2 |
| 리깅 | Make-It-Animatable, Blender auto weights, rigid | 리깅 성공률, 변형 품질 지표 | W3 |

- Hunyuan3D 계열은 라이선스 지역 제한(대한민국 제외) 때문에 **비교 대상에서 제외**한다. 이 결정과 근거도 보고서에 넣는다.

### B. 입력 데이터 전처리
- 모션: 미러링 해제, 캘리브레이션 기준 원점(어깨 중점)·스케일(어깨 너비) 정규화, visibility 마스킹.
- 3D: 배경 제거 → 피사체 bbox 크롭 → 정사각 패딩(여백 10%) → 모델 입력 해상도 리사이즈 → (선택) 대비 보정. 사용자 가이드: 정면 전신, A-pose 실루엣 템플릿.

### C. 추론 파이프라인 설계
- 모션: `requestVideoFrameCallback` → `detectForVideo` (VIDEO 모드, GPU delegate는 PoC로 확인) → 필터 → 분류기 → 이벤트. 메인 스레드와 Worker 배치는 PoC로 비교한다.
- 3D: Postgres 큐 → 단계별 워커 → 단계 산출물 저장 → 실패 단계부터 재시작.

### D. 출력 후처리
- 모션: 히스테리시스, 쿨다운, 신뢰도 게이트, 중복 펀치 억제.
- 3D: 정점 감축(목표 10~15k tris), 텍스처 1024px, 원점·축·키 정규화, meshopt 압축, 공통 스켈레톤 바인딩.

### E. 추론 속도 최적화
- 모션: lite 모델, 입력 해상도 축소(640×480 → 필요 시 480×360), 프레임 스킵 정책, WebGL GPU delegate.
- 3D: 모델 웜 상태 유지(워커 상주), 해상도·스텝 수 조절, 배치 없이 단건 처리, 동일 이미지 캐시(sha256).

## 3. 지표 정의 — 모션 인식

| 지표 | 정의 | 측정 방법 | 목표 |
|---|---|---|---|
| 동작별 Precision / Recall / F1 | 라벨 이벤트와 예측 이벤트를 ±200ms 윈도우로 매칭 | 녹화 jsonl을 `packages/motion`에 Node(Vitest)로 리플레이 → `tools/datasets/eval.ts` | jab·straight ≥ 0.85, guard ≥ 0.9, slip ≥ 0.85 |
| 오인식 펀치율 | 대기 상태(idle 라벨) 1분당 strike 이벤트 수 | idle 2분 세션 리플레이 | ≤ 1회/분 |
| 손 혼동률 | lead/rear 뒤바뀐 비율 | 혼동 행렬 | ≤ 3% |
| 회피 판정 일관성 | 같은 회피 동작 20회 중 방향 정답 비율, 반복 세션 간 표준편차 | 스크립트 세션 | ≥ 90%, σ ≤ 5%p |
| 분류 지연 | 라벨 시작 시각 → 이벤트 발생 시각 | 리플레이 타임스탬프 차 | p50 ≤ 100ms |
| 추론 처리시간 | `detectForVideo` 호출 소요 | `performance.now()` 계측, 기기별 | lite p95 ≤ 25ms (내장 GPU 노트북, 추정 목표) |

### 매칭 규칙
- 예측 이벤트 하나는 라벨 하나에만 매칭된다(헝가리안 대신 시간순 탐욕 매칭으로 충분).
- 손이 다르면 FP 1 + FN 1로 센다.
- guard·slip처럼 지속 상태인 동작은 구간 IoU ≥ 0.5를 TP로 친다.

## 4. 지표 정의 — 게임·네트워크·3D

### 4.1 게임 성능
| 지표 | 측정 | 목표 |
|---|---|---|
| 평균 FPS / p95 프레임 시간 | `requestAnimationFrame` 간격 60초 수집, 디버그 화면 그래프 | p95 ≤ 25ms |
| 입력→화면 지연 (파이프라인) | `requestVideoFrameCallback` 메타데이터 `captureTime`(지원 시) 또는 `expectedDisplayTime` → 분류 완료 → 애니메이션 첫 렌더 프레임 타임스탬프 | p50 ≤ 150ms |
| 입력→화면 지연 (종단) | 240fps 스마트폰 슬로모션으로 사람 손과 모니터를 한 화면에 촬영, 손목 동작 시작 프레임부터 화면 글러브 이동 프레임까지 세기(10회 평균) | p50 ≤ 150ms |
| 초기 로딩 | 첫 진입 → 플레이 가능까지(모델·에셋 포함), 콜드/웜 | 콜드 ≤ 8s (추정 목표, 국내 일반 회선) |
| 메모리 | Chrome Performance Monitor JS heap + GPU | 기록용 |

### 4.2 멀티플레이어
| 지표 | 측정 | 목표 |
|---|---|---|
| RTT | `time:ping` 샘플 p50/p95 | 기록용 |
| 판정 불일치 | 공격자 화면에서 "맞았다고 보였는데 dodged" 사례. 클라이언트 로컬 예측 판정(디버그 전용)과 서버 결과를 비교 기록 | RTT 100ms 조건에서 ≤ 5% |
| 재접속 복구 | 연결 강제 차단 → FIGHTING 복귀 시간 | ≤ 20s, 성공률 100% |
| 대역폭 | 업링크 bytes/s | ≤ 2 KB/s |

### 4.3 3D 생성
| 지표 | 정의 | 원천 |
|---|---|---|
| 생성 성공률 (Tier별) | T2/T1/T0 최종 도달 비율 | `ai_jobs`, `characters.tier` |
| 평균·p95 생성시간 | QUEUED 제외 처리시간, 단계별 분해 | `ai_job_stages.metrics.durationMs` |
| 리깅 성공률 | 검증 통과한 smooth 비율, rigid 강등 비율 | `VALIDATING/report.json` |
| 관절 변형 품질 | 테스트 포즈 6종(잽 끝, 스트레이트 끝, 가드, 피격, 숙임, KO)에서 **최대 엣지 늘어남 비율**(포즈 엣지 길이 / 레스트 엣지 길이), 상위 1% 엣지 평균 | 검증 스크립트 |
| 폴리곤 수 / GLB 크기 / 텍스처 크기 | 최종 에셋 메타 | `character_assets.meta` |
| GPU 메모리 피크 | `torch.cuda.max_memory_allocated` | stage metrics |
| 브라우저 로딩 시간 | GLB fetch + 파싱 | 클라이언트 계측 |

- 변형 품질 합격선(초기값, PoC로 조정): 최대 늘어남 비율 ≤ 2.5, 상위 1% 평균 ≤ 1.6. 넘으면 smooth를 실패로 보고 rigid로 강등한다.

## 5. 개선 전후 실험 설계

모든 실험은 **같은 고정 데이터셋**과 **같은 평가 스크립트**로 돌리고, 결과를 `tools/datasets/reports/{date}-{experiment}.md`로 남긴다.

| 실험 ID | 기준(Before) | 개선(After) | 지표 | 데이터 |
|---|---|---|---|---|
| M1 | 규칙 v1(고정 임계값) | 사용자 캘리브레이션 정규화 적용 | F1, 손 혼동률 | 모션 셋 |
| M2 | 필터 없음 | One Euro 필터 | 오인식률, 분류 지연 | idle + 스크립트 |
| M3 | 2D 손목 속도 단독 | + 손 겉보기 크기 증가·팔꿈치 각 다중 단서 | jab/straight Recall | 정면 펀치 세션 |
| M4 | Pose lite | Pose full | F1, 추론 ms, FPS | 모션 셋 + 기기 3종 |
| M5 | 규칙 v2(튜닝 완료) | 소형 학습 분류기(GBDT/1D-CNN, 윈도우 특징) | F1 | 학습/평가 사람 단위 분리 (조건부: 규칙 F1 < 0.85일 때만) |
| G1 | 전처리 없음(원본 이미지) | 배경 제거 + 크롭/패딩 | 생성 성공률, 육안 품질 | 3D 셋 |
| G2 | 모델 A | 모델 B (PoC 후보들) | 성공률, 시간, VRAM | 3D 셋 |
| R1 | smooth 단독 | smooth + 검증 + rigid 강등 | 최종 사용 가능률, 변형 지표 | 3D 셋 |
| P1 | 메인 스레드 추론 | Worker / 해상도 축소 | FPS, 지연 | 기기 3종 |

- 사람 단위로 학습/평가를 분리한다(같은 사람 데이터가 양쪽에 섞이면 F1이 부풀려진다).
- 각 실험은 1개 변수만 바꾼다.

## 6. 테스트 데이터 수집

### 6.1 모션 데이터셋
- 참가자: 팀원 7명 + 외부 동의자 5명 이상(키·체형·성별·안경 착용 다양화).
- 조건 조합: 조명(밝음/역광/어두움), 거리(1.2m/1.8m/2.5m), 의상(반팔/긴팔/검은 옷), 카메라(노트북 내장/외장 웹캠).
- 스크립트 세션(약 8분/인):
  1. idle 2분 (자연스러운 움직임, 말하기, 머리 긁기 포함 → 오인식 측정)
  2. 화면 프롬프트 "잽!"에 맞춰 잽 ×20, 스트레이트 ×20 (무작위 간격 1.5~3s)
  3. 가드 유지 ×10 (각 2s)
  4. 좌·우 회피 ×20씩, (확장) 숙이기 ×20
  5. 자유 콤보 1분 (라벨은 사후 수동 보정)
- **라벨링**: 가이드 프롬프트 표시 시각을 약한 라벨로 기록하고, 수집 도구에서 타임라인을 보며 시작·끝을 보정한다(디버그 화면의 녹화 모드).
- 저장: 랜드마크 jsonl.gz만 저장하고 영상은 저장하지 않는다. 동의서를 받는다(09-DATA-MODEL 7절).
- 분할: 학습/튜닝 8명, 평가 4명 이상(사람 단위).

### 6.2 E2E용 영상 픽스처 (예외)
- Playwright 가짜 웹캠 테스트에는 **팀원 본인이 동의한 짧은 y4m 영상 3~5개**만 쓴다. 비공개 저장소 또는 Git LFS에 두고 공개 저장소에는 올리지 않는다.

### 6.3 3D 테스트 이미지셋 (20~30장)
| 범주 | 수 | 예 |
|---|---|---|
| 사람형 손그림(A-pose 템플릿 사용) | 6 | 팀원 그림 |
| 사람형 자유 그림 | 4 | 측면·역동 포즈 포함 |
| 로봇 | 5 | 박스형, 인간형 로봇 |
| 만화/치비 캐릭터 | 5 | 머리 큰 비율(직접 그림 또는 CC0) |
| 동물형 이족 | 3 | 곰, 고양이 |
| 실패 예상 케이스 | 4 | 배경 복잡, 일부만 그려짐, 다수 인물, 매우 얇은 팔 |

- 저작권이 있는 캐릭터 이미지는 쓰지 않는다. 팀 창작물 또는 CC0만 쓴다.

## 7. 자동화 테스트

| 계층 | 도구 | 대상 |
|---|---|---|
| 단위 | Vitest | `packages/combat`(프레임 데이터, 판정, 경직, KO), `packages/motion`(필터, 상태 머신, 정규화), `packages/shared` 스키마 |
| 리플레이 회귀 | Vitest + 녹화 jsonl | 평가셋 F1이 기준선보다 0.02 이상 떨어지면 CI 실패 |
| 서버 통합 | Vitest + Colyseus testing + 가상 클라이언트 2개 | 룸 플로우, 재접속, 부정 입력 거부, `SIM_LATENCY_MS` 0/50/100/200ms에서 판정 결과 분포 |
| E2E 브라우저 | Playwright (Chromium) | 실행 플래그 `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream --use-file-for-fake-video-capture=fixtures/jab_x5.y4m` → 캘리브레이션 통과, 잽 이벤트 ≥ 4회, HUD 반영 확인 |
| AI 워커 | pytest | 단계 함수 단위(정규화·감축·검증 지표), 큐 점유/재시도, GPU 없는 CI에서는 생성 단계를 픽스처 GLB로 대체 |
| 성능 회귀 | 수동 + 스크립트 | 주 1회 기기 3종에서 FPS/지연 측정표 갱신 |

- CI: GitHub Actions에서 단위·리플레이·서버 통합·E2E(헤드리스, 가짜 웹캠)를 돌린다. GPU 단계는 CI 제외.
- Playwright 가짜 웹캠은 Chromium 전용 플래그다. y4m은 `ffmpeg -i in.mp4 -pix_fmt yuv420p out.y4m`으로 만든다(용량이 커서 짧게 자른다).
